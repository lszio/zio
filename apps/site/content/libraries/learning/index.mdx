## 两条学习路径

Learning 既包含从输入输出样本搜索 S 表达式的符号学习器，也包含面向张量后端的模型训练接口。反馈仲裁、配方声明、模型候选生命周期、种群分配与经验索引是显式策略模块，不必为了使用其中一个模块就采用整个应用。

### 从样本搜索一个函数

候选程序可以作为普通 Lisp 数据解析、检查和评分，再包装为可调用函数。下面的形式来自仓库 `examples/learn-demo.zio`：

```lisp
(load "libs/learning/learn.zio")

(def samples '[[1 3] [2 5] [3 7]])
(def cfg
  {:ops '[+ - *]
   :constants '[0 1 2]
   :max-depth 2
   :beam-width 24})

(def f (learn--wrap-function (learn-function samples cfg)))
(f 10)
```

这里的样本符合 `y = 2x + 1`。学习器在配置限定的搜索空间里寻找低误差、较小的表达式；样本上的表现不证明对任意输入正确，也不保证搜索一定得到期望程序。

默认提案器是枚举器，也可提供 `(fn [task history] candidates)`，例如 [Loom 的模型提案器](/libraries/loom/)。候选以字符串进入循环，经过解析、封闭词汇白名单、规范化去重和评分。代际预算、AST 节点上限和求值预算由配置控制；`:max-evals` 默认零表示无限制，使用前应为自己的任务选择实际边界。这不是任意不可信代码的通用进程沙箱。

### 用稳定接口驱动训练

`runner.zio` 是面向编排方的入口，提供模型构建、训练步、评估、快照导入导出、特征空间查询与 rollout。训练步接收配方和数据行，不把训练方法藏在调用方的特殊分支里。

当前配方包含监督学习、硬／软蒸馏、偏好、示范、自监督、环境反馈和策略梯度；源码将损失构造为张量操作，并通过反向传播与 Adam 更新。当前特征转换面向明确声明的 256 像素加 2 读数空间，可包含两个 presence 标志；环境 rollout 面向受限 lineworld。它们是具体的当前接口，不是任意数据模态、任意环境或通用自主学习系统的承诺。

快照携带空间 id、宽度、编码器与版本信息，不匹配的空间会拒绝导入。训练来源许可检查拒绝已撤回、禁止使用或仅供展示的记录；源许可不能靠模型分数代替。

## 加载与宿主要求

上面的符号搜索示例用可读取仓库源码的原生会话，从仓库根目录加载；不需要真实模型提供者。浏览器必须先引入定义，不能直接假定本地 `load` 路径存在。

训练入口使用 `(load "libs/learning/runner.zio")`，它会加载 runtime 与配方模块。真正构建、训练和恢复模型需要宿主张量后端句柄与 `host/tensor-call` 等能力；二进制数据集读写和计数器操作还依赖相关文件、缓冲与二进制绑定。只加载源码不等于配置好了训练后端。

反馈、模型描述、配方和分配策略主要处理输入数据；持久化、权限与事务由应用宿主管理。库中的 Grove 特征空间与训练策略有明确应用背景，不应宣称为独立的完整通用训练平台。
