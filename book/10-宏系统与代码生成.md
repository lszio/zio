# 10 - 宏系统与代码生成

## 宏是什么？

**宏 = 在编译期运行的函数**。

普通函数接收值（Value），返回值（Value）。宏接收代码（Sexp），返回代码（Sexp）。

```
普通函数: (square 5) → 求值 5 → 25（值）
宏:       (unless false 42) → 展开 → (if false nil 42)（新代码）
```

## 最简单的宏

```lisp
(defmacro unless [test body]
  (list 'if test nil body))
```

宏调用时发生了什么？

```
输入: (unless false 42)

宏展开: (list 'if false nil 42)
       → (if false nil 42)

重新求值: (if false nil 42) → nil
```

`unless` 的展开结果是一个完全合法的 Zio 表达式——`if`。Zio 不需要在内核中理解 `unless`，宏把它翻译成了内核已经懂得的东西。

## 宏是语言实现者的特权

Zio 的定理 3：**宏是用户扩展 eval 的方式**。

这意味着：
- 用户能做的 = 语言实现者能做的
- 不需要改 Rust 代码就能添加新语法
- 宏可以改变求值策略（比如延迟求值）

看一个更有用的例子——`defn` 在理论上也可以用宏实现：

```lisp
;; defn 实际上 = def + fn
(defmacro defn [name params & body]
  (list 'def name (cons 'fn (cons params body))))
```

当然，`defn` 在 Zio 中是特殊形式（性能原因），但这说明宏可以做"语法变换"。

## Zio 的宏定义

打开 `core/src/macros.rs`，核心函数 `apply_macro`：

```rust
pub fn apply_macro(m: &Macro, args: &[Sexp], _env: &Arc<Env>, engine: &dyn EvalEngine)
    -> Result<Sexp, EvalError>
{
    // 1. 绑定宏参数
    let new_env = Env::bind(&m.env, &m.params, &args_to_value(args))?;

    // 2. 在绑定的环境中求值宏体
    let result = engine.eval_expr(&m.body, &new_env, false)?;

    // 3. 结果必须是 Sexp（代码），转回来
    value_to_sexp(&result.into_value())
}
```

过程很清晰：
1. 把宏调用的实参（Sexp）绑定到宏的形参
2. 执行宏体（宏体是在用户环境中求值的普通 Zio 代码）
3. 确保结果可以转回 Sexp（代码），返回给 eval 重新求值

## 宏展开的流程

回到 `eval_inner` 看宏的调用路径：

```rust
// 在 eval_inner 中：
Sexp::List(vec) => {
    let first = &vec[0];
    let args = &vec[1..];

    // ... 先检查特殊形式 ...

    // eval first → 得到函数值
    let func_val = eval_inner(first, env, false, engine)?;

    // 如果是宏 → 展开！
    if let Value::Macro(m) = &func_val {
        let expanded = apply_macro(m, args, env, engine)?;  // 宏展开
        return eval_inner(&expanded, env, tail, engine);    // 重新求值
    }

    // 否则是普通函数
    // eval 所有参数 → apply
}
```

关键点：宏展开后的结果**重新进入 eval 循环**。所以宏展开的结果可以再包含宏调用——递归展开直到没有宏为止。

## Macro 结构

```rust
pub struct Macro {
    pub name: String,
    pub params: Vector<String>,     // 参数名（Sexp 直接绑定，不求值）
    pub body: Sexp,                 // 宏体
    pub env: Arc<Env>,              // 宏定义时的环境（闭包！）
}
```

注意：宏的 `params` 绑定的是**未求值的 Sexp**。宏的参数是代码片段，不是值。

## syntax-rules：模式匹配宏

除了 `defmacro`，Zio 还支持 `syntax-rules`——模式匹配风格的宏（类似 Scheme 的 hygienic macro）：

```lisp
(defmacro swap
  (syntax-rules []
    [(swap a b) (let [tmp a] (set! a b) (set! b tmp))]))
```

`syntax-rules` 的工作原理在 `macros.rs` 中：

```rust
pub fn expand_syntax_rules(rules: &Sexp, args: &[Sexp]) -> Result<Sexp, EvalError> {
    // rules = (syntax-rules (literal ...) (pattern template) ...)
    // args = 宏调用的实参

    for rule in ... {
        // 尝试匹配 pattern
        if match_pattern(pattern, args, literals, &mut bindings) {
            // 模式匹配成功！用 bindings 展开 template
            return Ok(expand_template(template, &bindings, literals));
        }
    }
    // 没有匹配 → 错误
}
```

## 宏系统的测试

```lisp
;; 在 eval.rs 测试中
(defmacro unless [test then else?]
  (list 'if test nil then))

(macroexpand-1 '(unless false 42))   ;; → (if false nil 42)
```

测试宏的最直观方式就是 `macroexpand-1`——看宏展开成了什么。

## 动手实验

```lisp
;; 1. 简单的宏：双倍
(defmacro double [expr]
  (list '* 2 expr))

(double 21)  ;; → 42

;; 2. 计时宏
(defmacro time [expr]
  (list 'let '[start (now)]
    (list 'do
      expr
      (list 'println "took" (list '- (list 'now) 'start)))))

;; 3. 条件执行
(defmacro when [test & body]
  (list 'if test (cons 'do body)))

(when true
  (println "This runs"))
(when false
  (println "This does NOT run"))

;; 4. 查看宏展开
(macroexpand-1 '(when true (println "hi")))
;; → (if true (do (println "hi")))
```

## 宏 vs 普通函数

| | 普通函数 | 宏 |
|---|---|---|
| 参数状态 | 先求值后调用 | 不求值直接绑定 |
| 输入 | Value | Sexp |
| 输出 | Value | Sexp |
| 执行时机 | 运行时 | 编译/展开时 |
| 参数数量 | 固定 | 灵活（& rest） |
| 用途 | 计算 | 语法变换 |
