# 12 - 模块系统与包管理

## 为什么需要模块？

当程序变大，你需要：
1. **组织代码**：把相关的函数放在一起
2. **控制可见性**：只暴露 API，隐藏实现
3. **避免命名冲突**：不同模块可以有同名函数

Zio 的模块系统提供了这些能力。

## Module 结构

打开 `core/src/module.rs`：

```rust
pub struct Module {
    pub name: Vec<String>,       // 模块名，如 ["zio", "math"]
    pub env: Arc<Env>,           // 模块自己的环境
    pub exports: Vec<String>,    // 显式导出的符号
    pub source: Option<SourceId>, // 来源文件
}
```

模块名是分层的：`["zio", "math"]` 表示 `:zio.math`。

## 声明模块：module

```lisp
;; 定义一个模块
(module :zio.shapes
  (:export circle-area rectangle-area PI)

  (def PI 3.14159)

  (defn circle-area [r]
    (* PI r r))

  (defn rectangle-area [w h]
    (* w h))

  ;; 这个函数没有导出，外部不可见
  (defn internal-helper [x]
    (* x 2)))
```

模块的工作原理：

```
(module :zio.shapes (:export ...) body...)
        │
        ▼
1. 创建子环境（child env），外层指向当前环境
        │
        ▼
2. 在子环境中求值 body 中的每个表达式
        │
        ▼
3. 记录导出的符号名
        │
        ▼
4. 把 Module 注册到全局模块表
```

```rust
pub fn do_module(args, env, engine) -> Result<TailResult, EvalError> {
    // 1. 解析模块名
    let module_name = parse_module_name(&args[0])?;  // "zio.shapes" → ["zio", "shapes"]

    // 2. 解析 :export 子句
    let (body_start, exports) = parse_export_clause(&args[1..]);

    // 3. 创建子环境
    let module_env = Arc::new(Env::new(Some(env.clone())));

    // 4. 在子环境中求值
    let body = &args[body_start..];
    let result = eval_last_body(body, &module_env, true, engine)?;

    // 5. 注册模块
    let module = Module {
        name: module_name,
        env: module_env,
        exports,
        source: None,
    };
    engine.register_module(module);
    Ok(result)
}
```

## 加载模块：require

```lisp
;; 使用 :refer 选择性导入
(require :zio.shapes :refer [circle-area])

(circle-area 5)  ;; → 可用
rectangle-area    ;; → 错误！没有导入

;; 使用 :as 创建别名
(require :zio.shapes :as shapes)
(shapes/circle-area 5)  ;; → 可用（通过别名前缀）

;; 同时使用 :as 和 :refer
(require :zio.shapes :as s :refer [PI])
PI          ;; → 3.14159
(s/circle-area 5)  ;; → 可用
```

`require` 的实现逻辑：

```rust
pub fn do_require(args, env, engine) -> Result<TailResult, EvalError> {
    let module_name = parse_module_name(&args[0])?;

    // 1. 检查是否已加载
    if !engine.is_module_loaded(&module_name) {
        // 2. 查找并加载模块文件
        let source = load_module_source(&module_name)?;
        engine.call_loader(&module_name, &source, env)?;
    }

    // 3. 找到已加载的模块
    let module = engine.find_module(&module_name).unwrap();

    // 4. 处理 :as 别名
    if let Some(alias) = as_name {
        // 创建别名 map
        let alias_map = create_alias_map(&module);
        env.set(alias, Value::Map(alias_map));
    }

    // 5. 处理 :refer 选择性导入
    if let Some(symbols) = refer_list {
        for sym in symbols {
            let val = module.env.get(&sym);
            env.set(sym, val);  // 导入到当前环境
        }
    }

    Ok(TailResult::Value(Value::Nil))
}
```

## 模块解析：文件在哪里？

模块名通过 `resolve_module_path` 映射到文件路径：

```rust
pub fn resolve_module_path(path: &str) -> Result<PathBuf, EvalError> {
    // 查找路径：
    // 1. 当前目录: ./{path}.zio
    // 2. ZIO_PATH 环境变量中的目录

    let candidates = [
        format!("./{}.zio", path.replace('.', "/")),       // "zio.shapes" → "./zio/shapes.zio"
        format!("{}/{}.zio", ZIO_PATH, path.replace('.', "/")),
    ];

    for candidate in &candidates {
        if Path::new(candidate).exists() {
            return Ok(PathBuf::from(candidate));
        }
    }
    Err(EvalError::module_not_found(path))
}
```

## ModuleTable：模块注册表

```rust
pub struct ModuleTable {
    modules: HashMap<Vec<String>, Module>,
    loading: HashSet<PathBuf>,  // 正在加载中的文件（防循环依赖）
}

impl ModuleTable {
    pub fn register(&mut self, name: Vec<String>, module: Module);
    pub fn find(&self, name: &[String]) -> Option<Module>;
    pub fn is_loaded(&self, name: &[String]) -> bool;
    pub fn begin_loading(&mut self, path: &Path);  // 标记开始加载
    pub fn end_loading(&mut self, path: &Path);    // 标记加载完成
}
```

`loading` 集合防止循环依赖：如果模块 A 引用了模块 B，而 B 又引用了 A，`begin_loading` 会检测并报错。

## 包管理系统（Package）

除了 `module`，ZOS 还有一个 `defpackage`：

```lisp
(defpackage :zio.math
  (:use :zio.core)     ;; 继承 :zio.core 的符号
  (:export :pi :sin :cos :tan))
```

`Package` 是更完整的符号命名空间管理：

```rust
pub struct Package {
    pub name: String,
    pub symbols: HashMap<String, Value>,   // 内部符号表
    pub exports: HashSet<String>,           // 显式导出的符号
    pub uses: Vec<String>,                  // 继承的包
    pub imports: HashMap<String, String>,   // 从其他包导入的符号
}
```

## REPL 中的模块加载

在 CLI 中，模块通过 `require` 加载文件：

```lisp
;; 加载当前目录的 shapes.zio
(require :shapes)

;; 加载标准库
(require :zio.core)
(require :zio.math)

;; 加载多个模块
(require :zio.datalog)
(require :zio.agent)
```

CLI 的加载器实现：

```rust
// cli/src/main.rs
fn make_require_loader(sm: &Arc<SourceMap>) -> Box<zio_core::context::ModuleLoader> {
    Box::new(move |mod_name, source, parent_env| {
        // 1. 解析文件路径
        let path = resolve_module_path(&mod_name.join("."))?;
        // 2. 读取文件
        let source = read_source_file(&path)?;
        // 3. 解析 Sexp
        let exprs = parse_all(&source);
        // 4. 依次求值
        for expr in exprs {
            eval(expr, engine)?;
        }
        // 5. 返回模块
        Ok(Module { name: mod_name, ... })
    })
}
```

## 动手实验

创建两个文件：

**math.zio**:
```lisp
(module :math
  (:export add multiply PI)

  (def PI 3.14159)

  (defn add [a b] (+ a b))
  (defn multiply [a b] (* a b))
  (defn secret [x] (* x 100)))   ;; 不导出
```

**main.zio**:
```lisp
(require :math :refer [add PI])
(println (add PI 2))    ;; → 5.14159
;; (secret 5)           ← 错误，secret 未导出
```

然后在 REPL 中：

```lisp
(load "main.zio")
```

## 核心记忆

> **模块 = 命名空间 + 控制导出。** `module` 声明模块，`require` 加载并使用模块。`defpackage` 提供更强大的符号管理。
