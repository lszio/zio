# 01 - Zio 是什么：项目概览与设计哲学

> 2026-10-07 目录更新：本文教学代码与旧阶段/验收描述保留历史语境；源码链接和运行路径已映射到当前位置。现行目标是 `libs/` 的 Zio 库与 `apps/grove/` 的 Zio 业务迁移，Rust Grove 业务尚未整体重写；通用 Rust transport/host adapter 在 `contribs/native/loom/`。当前归属见[架构](../docs/zio-architecture.md)与[批准目录计划](../docs/superpowers/plans/2026-10-07-language-first-layout.md)。

## 一句话

**Zio 是一门现代 Lisp，当前核心由 Rust 实现，目标是逐步让展开、分析与编译由 Zio 自身承载（Planned）**。它的代码长这样：

```lisp
;; 一个简单的 Zio 程序
(defn greet [name]
  (str "Hello, " name "!"))

(greet "World")  ;; → "Hello, World!"
```

看着像 Lisp，对不对？没错——Zio 就是 Lisp 大家族的一员：括号在前、无关键字散落、代码就是数据。

但 Zio 不是"另一个 Lisp 方言"。它有明确的时代定位：

```
Zio = Lisp 核心（代码即数据 + 求值/调用 + 宏）
    + Rust 宿主（高性能 + 可嵌入 + FFI）
    + ZOS 对象系统（类 + 多分派 + 反射）
官方 Zio 库 = Numa（计算） / Rill（CLI 组合） / Loom（Agent harness）（Planned）
独立应用 = Grove（消费语言与库，持学习与发布治理；新主线 Planned）
```

三库按需安装、独立版本发布，不属于 Zio 语言内置特性，核心没有对库或
Grove 的反向依赖。正式短名不等于已确认注册包 ID；当前源码/命令不改名，
未来规范目录与逻辑命名空间见[术语表](../docs/glossary.md)，边界见
[ADR-019](../docs/adrs.md#adr-019-grove-独立应用与同像性逻辑演化)。

## Zio 的两个面向

### 面向用户：一门 Lisp 语言

当你用 Zio 编程时，你写的是 Lisp：

| 特性 | 示例 |
|------|------|
| 算术 | `(+ 1 2 3)` → `6` |
| 函数定义 | `(defn add [a b] (+ a b))` |
| 匿名函数 | `(fn [x] (* x x))` |
| 条件 | `(if (> x 0) "正数" "非正数")` |
| 递归 | `(defn fact [n] (if (<= n 1) 1 (* n (fact (- n 1)))))` |
| 宏 | 用 Lisp 写 Lisp 的代码生成器 |

### 面向实现者：一个 Rust crate

当你打开 `langs/core/src/`，你看到的是 Rust：

```
langs/core/src/
├── lib.rs           # 模块入口
├── sexp.rs          # 代码的数据结构
├── value.rs         # 运行时的值
├── eval.rs          # eval/apply 循环
├── env.rs           # 词法环境
├── context.rs       # 求值上下文
├── builtins/        # 内置函数（按域分模块）
├── macros.rs        # 宏引擎
├── error.rs         # 错误类型
├── span.rs          # 源码位置
├── reader/          # 词法分析 + 解析
└── special/         # 特殊形式
    ├── bindings.rs  # def, defn, defmacro, fn
    ├── control.rs   # if, do, and, or, cond
    ├── letloop.rs   # let, loop, recur
    ├── data.rs      # quote
    └── module_forms.rs  # module, require
```

以上是解释器核心的教学地图，不是当前工作区的完整清单；实际工作区成员以 Cargo manifest 为准。

## 五个设计定理

Zio 不是随意堆砌的特性集合。它由五个定理推导而来：

### 定理 1：所有可变状态必须显式

**意思**：不要隐藏的全局变量。所有状态都放在 `EvalContext` 里，通过参数传递。

**为什么**：如果状态藏在全局变量里，你没法同时跑两个解释器、没法隔离测试、没法把 Zio 嵌入到你的 Rust 程序里。

**看代码**：打开 `langs/core/src/context.rs`——这是目前唯一的"全局状态"容器：

```rust
pub struct EvalContext {
    pub env: Arc<Env>,              // 当前环境
    pub modules: RefCell<ModuleTable>,  // 已加载的模块
    pub loader: RefCell<Option<Box<ModuleLoader>>>,  // 模块加载器
}
```

所有状态都在这了。够显式吧。

### 定理 2：Rust 是合同边界，Lisp 是组合层

**意思**：性能关键路径用 Rust 写（NativeFn）。Lisp 层负责组合、策略、元编程。

**为什么**：Rust 写底层函数确保性能正确；Lisp 用宏和高阶函数组合这些原语——两层分工明确。

**看代码**：在 `langs/core/src/builtins/numeric.rs` 中，`+` 运算符的实现：

```rust
pub fn add(args: Vector<Value>, _engine: &dyn EvalEngine) -> Result<Value, EvalError> {
    // Rust 原语示意；调用仍有参数求值、类型检查与动态值开销
    let mut sum = 0i64;
    for arg in &args {
        if let Value::Integer(n) = arg { sum += n; }
    }
    Ok(Value::Integer(sum))
}
```

这个 Rust 函数被安装到 Lisp 环境中，从 Lisp 层调用 `(+ 1 2 3)` 就跳到了这段 Rust 代码。

### 定理 3：宏是用户扩展 eval 的方式

**意思**：用户能写和语言实现者一样的"语法扩展"。

**为什么**：这是 Lisp 同像性的核心价值。用 Zio 写一个自己的 `unless`（除非）：

```lisp
(defmacro unless [test body]
  (list 'if test nil body))

(unless false 42)   ;; → 42
(unless true 42)    ;; → nil（不执行）
```

这看起来像新语法，但完全用 Zio 宏实现，没改一行 Rust。

### 定理 4：核心收敛职责，应用独立

**意思**：ZOS 的 Object/Class/GF/Method/MOP 方向属于语言核心，不应移成可选业务库。核心不依赖 AI 或 Grove；公共能力只有出现真实复用才下沉。

**为什么**：Numa 负责连续数值数组/矩阵/向量与后端接口，不持学习治理；Rill 负责参数/子命令/帮助、命令组合、终端 I/O 与退出状态，不承担语言求值；Loom 负责模型/工具/会话/预算/取消/provider/ACP，不持 Grove 的学习目标、独立评价或发布。当前 Rust `loom` adapter 位于 `contribs/native/loom/`；`zio-cli` 是未来消费 Rill 的可执行入口，不等于组合库。Grove 是独立 APP，不是 library-first 或产品外壳。

### 定理 5：协议比实现重要

**意思**：`EvalEngine` trait 是所有扩展的契约。实现可以换，接口保持稳定。

**看代码**：`langs/core/src/context.rs` 中的 trait 定义：

```rust
pub trait EvalRuntime {
    fn eval_expr(&self, expr: &Sexp, env: &Arc<Env>, tail: bool)
        -> Result<TailResult, EvalError>;
    fn env(&self) -> &Arc<Env>;
}

```

任何实现了这个 trait 的东西都是一个 Zio 解释器。

## 当前状态与目标边界

当前 Rust 解释器与 ZOS 路径是学习起点；本章代码为机制示意，不是逐字 API 清单。当前统计与验证记录请读 [status](../docs/status.md)，旧版的 ~3,500 行 / 103 测试不能作为当前交付证据。

**Planned：编译器自举。** 用 Zio 编写展开、分析与编译，Rust 收敛为最小运行时、宿主边界与性能原语。这与“用 Zio 写编辑器或 APP”是两个不同验收项；同像性提供结构化表示和编辑能力，不意味着神经模型透明或程序已经证明正确。

**Planned：Grove 首个端到端验收。** 可执行 Zio agent 逻辑调用真实 LLM；生成代码经过解析、能力检查和隔离执行；错误与执行证据驱动修订。Web 展示源码、真实执行路径和 diff；反馈产生逻辑候选，经独立评估和人工批准才成为正式版本。自动实验、训练和 checkpoint 仅限已批准预算与编辑范围；ZOS/编译器可信基线、鉴权、评估器、checkpoint 与发布守卫不得由候选自行修改。

`agent.zio` 的固定回应已由真实 agent 循环替换（G02，受控端点验证、无 live 凭据），ACP 尚未实现；CPU torch 示例确有计算，但服务 train/resume 只有队列记录、没有训练 dispatcher。冻结/可训练约束尚未进入优化器与联合提交；`learned_into` 记录冻结数据集成员，不证明训练消费；progress 事件是当前记录的合成投影。静态 site 和模拟 Q-learning 不是 Grove 产品 Web 或真实 harness，LLM 自述也不是执行证据。

**Planned：ACP（Agent Client Protocol）。** 双向协议目标先实现 client 与 teacher adapter，再实现 server；Loom 负责协议接入，Grove 负责学习与发布治理，不把 ACP 支持等同于学习闭环完成。

## 小结

Zio 是一门"小而完整"的 Lisp：

- **收敛**：按真实职责维护核心，而非以历史行数或“其余皆库”定义边界
- **完整**：有完整的 eval/apply、宏、对象系统、模块系统
- **可嵌入**：任何 Rust 程序都可以引入 Zio 作为脚本引擎
- **可扩展**：宏 + ZOS MOP 构成四个扩展层次
