# 01 - Zio 是什么：项目概览与设计哲学

## 一句话

**Zio = 用 Rust 写的一门 Lisp 编程语言**。它的代码长这样：

```lisp
;; 一个简单的 Zio 程序
(defn greet [name]
  (str "Hello, " name "!"))

(greet "World")  ;; → "Hello, World!"
```

看着像 Lisp，对不对？没错——Zio 就是 Lisp 大家族的一员：括号在前、无关键字散落、代码就是数据。

但 Zio 不是"另一个 Lisp 方言"。它有明确的时代定位：

```
Zio = Lisp 核心（代码即数据 + 求值/调用 + 宏）
    + Rust 宿主（高性能 + 可嵌入 + FFI）
    + ZOS 对象系统（类 + 多分派 + 反射）
    + 扩展库（Datalog · Agent · AI 框架）
```

## Zio 的两个面向

### 面向用户：一门 Lisp 语言

当你用 Zio 编程时，你写的是 Lisp：

| 特性 | 示例 |
|------|------|
| 算术 | `(+ 1 2 3)` → `6` |
| 函数定义 | `(defn add [a b] (+ a b))` |
| 匿名函数 | `(fn [x] (* x x))` |
| 条件 | `(if (> x 0) "正数" "非正数")` |
| 递归 | `(defn fact [n] (if (<= n 1) 1 (* n (fact (- n 1)))))` |
| 宏 | 用 Lisp 写 Lisp 的代码生成器 |

### 面向实现者：一个 Rust crate

当你打开 `core/src/`，你看到的是 Rust：

```
core/src/
├── lib.rs           # 模块入口
├── sexp.rs          # 代码的数据结构
├── value.rs         # 运行时的值
├── eval.rs          # eval/apply 循环
├── env.rs           # 词法环境
├── context.rs       # 求值上下文
├── builtins.rs      # 30 个内置函数
├── macros.rs        # 宏引擎
├── error.rs         # 错误类型
├── symbol.rs        # 符号
├── span.rs          # 源码位置
├── reader/          # 词法分析 + 解析
└── special/         # 特殊形式
    ├── bindings.rs  # def, defn, defmacro, fn
    ├── control.rs   # if, do, and, or, cond
    ├── letloop.rs   # let, loop, recur
    ├── data.rs      # quote
    └── module_forms.rs  # module, require
```

就这些。约 3,500 行 Rust 代码，实现了一个完整的 Lisp 语言。

## 五个设计定理

Zio 不是随意堆砌的特性集合。它由五个定理推导而来：

### 定理 1：所有可变状态必须显式

**意思**：不要隐藏的全局变量。所有状态都放在 `EvalContext` 里，通过参数传递。

**为什么**：如果状态藏在全局变量里，你没法同时跑两个解释器、没法隔离测试、没法把 Zio 嵌入到你的 Rust 程序里。

**看代码**：打开 `core/src/context.rs`——这是目前唯一的"全局状态"容器：

```rust
pub struct EvalContext {
    pub env: Arc<Env>,              // 当前环境
    pub modules: RefCell<ModuleTable>,  // 已加载的模块
    pub loader: RefCell<Option<Box<ModuleLoader>>>,  // 模块加载器
}
```

所有状态都在这了。够显式吧。

### 定理 2：Rust 是合同边界，Lisp 是组合层

**意思**：性能关键路径用 Rust 写（NativeFn）。Lisp 层负责组合、策略、元编程。

**为什么**：Rust 写底层函数确保性能正确；Lisp 用宏和高阶函数组合这些原语——两层分工明确。

**看代码**：在 `core/src/builtins.rs` 中，`+` 运算符的实现：

```rust
pub fn add(args: Vector<Value>, _engine: &dyn EvalEngine) -> Result<Value, EvalError> {
    // Rust 实现的加法，零开销
    let mut sum = 0i64;
    for arg in &args {
        if let Value::Integer(n) = arg { sum += n; }
    }
    Ok(Value::Integer(sum))
}
```

这个 Rust 函数被安装到 Lisp 环境中，从 Lisp 层调用 `(+ 1 2 3)` 就跳到了这段 Rust 代码。

### 定理 3：宏是用户扩展 eval 的方式

**意思**：用户能写和语言实现者一样的"语法扩展"。

**为什么**：这是 Lisp 同像性的核心价值。用 Zio 写一个自己的 `unless`（除非）：

```lisp
(defmacro unless [test body]
  (list 'if test nil body))

(unless false 42)   ;; → 42
(unless true 42)    ;; → nil（不执行）
```

这看起来像新语法，但完全用 Zio 宏实现，没改一行 Rust。

### 定理 4：核心最小，其余是库

**意思**：核心只包含必需的东西。Datalog、Agent、AI 框架都是库。

**为什么**：核心小意味着稳定、可维护。领域能力可以独立演化、独立发布。

### 定理 5：协议比实现重要

**意思**：`EvalEngine` trait 是所有扩展的契约。实现可以换，接口保持稳定。

**看代码**：`core/src/context.rs` 中的 trait 定义：

```rust
pub trait EvalRuntime {
    fn eval_expr(&self, expr: &Sexp, env: &Arc<Env>, tail: bool)
        -> Result<TailResult, EvalError>;
    fn env(&self) -> &Arc<Env>;
}
```

任何实现了这个 trait 的东西都是一个 Zio 解释器。

## 小结

Zio 是一门"小而完整"的 Lisp：

- **小**：核心 ~3,500 行 Rust，概念正交、不重叠
- **完整**：有完整的 eval/apply、宏、对象系统、模块系统
- **可嵌入**：任何 Rust 程序都可以引入 Zio 作为脚本引擎
- **可扩展**：宏 + ZOS MOP 构成四个扩展层次
