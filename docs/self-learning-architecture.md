> 状态：整体设计基线；W00–W10 已实现为 Experimental（实现与验收证据见[交付计划](superpowers/plans/2026-10-02-self-learning.md)第 12 节与[特性矩阵](feature-matrix.md)），W11–W17 仍为 Planned。实现细节见已采纳的 [ADR-017](adrs.md)。
> 设计日期：2026-10-02。实现状态以 [特性矩阵](feature-matrix.md) 为准。
> 统一命名：产品与命令为 `grove`，学习宿主库 crate 为 `grove`，产品 crate 为 `grove-app`；它们基于 Zio，不另设中文产品名。现有 `zio-core`、`zio-ai` 等组件名称不变。
> 已确认方向：作为 Zio 的库或基于该库的产品；模型以代码组织，同时支持程序结构与神经权重学习；学习来源包括上游模型蒸馏和人类反馈纠正。
> 本次扩展方向：可恢复检查点、历史模型比较与选择、分支谱系、预算内的多路群体学习，以及内部模块独立演化。
> 本文提出具体边界与合同，API 名称均为设计记法，不是现有可调用接口。
> 配套：[整体交付计划](superpowers/plans/2026-10-02-self-learning.md)。本文定义能力与合同，计划定义工作包、依赖和验收；不维护第二份平行架构。

## 阅读摘要

目标是让模型作为“程序结构 + 参数 + 能力库”持续学习：接收多模态输入，吸收教师和人类等反馈，交替优化代码与权重，保存历史、分裂多个研究方向，并验证模块组合或群体协作的价值。

采用库优先、单机优先的实现基线：Zio 负责学习策略与程序表示，Rust 宿主负责持久化、权限、预算和进程隔离，外部张量后端负责训练，独立产品壳提供 API 与可视界面。不开发新的语言内核、自动微分框架或分布式数据库。

完整交付不止能提交任务或保存文件：必须真实训练、真实改写程序、真实恢复检查点、真实多 worker 运行，并实际验证人类纠正后的新候选；质量不达标时允许保留旧模型，但不允许用模拟输出替代这些机制。

## 1. 定位与已有基础

采用“可嵌入学习库 + 宿主能力 + 可选产品壳”，不是给 Zio core 增加内建训练系统，也不是只做一个聊天 Agent。应用可直接使用学习库；产品通过同一套接口增加交互、运行管理和发布操作。

模型定义为 `y = P(x; θ, L)`：P 是程序结构，θ 是参数，L 是精确版本绑定的能力库。学习包括参数优化、程序改写和能力抽象。权重可以是外部二进制制品，不要求展开成源码字面量。

### 1.1 当前证据

| 位置 | 已有能力 | 不能据此宣称的能力 |
|---|---|---|
| `lib/zio/learn.zio` | 数值表达式候选解析、闭世界检查、代际评分、预算 | 通用多模态学习、张量训练、版本发布 |
| `lib/zio/proposer.zio` | 文本候选提议与历史反馈 | 教师蒸馏协议、人类纠正接口 |
| `ai/src/lib.rs` | 文本 `LlmHost` / `EmbedHost`、外部 install | 图像/音频内容协议、自动微分和训练能力 |
| `docs/synthesis-plan.md` | L1–L4 程序合成与经验规划 | 已实现的经验库或训练后端 |

本次讨论前已运行 `cargo run -p zio-cli -- examples/learn-demo.zio`：线性示例 f(10)=21、平方示例 f(6)=36、确定性检查为 true。该证据仅覆盖已有数值学习示例。

### 1.2 与已有设计的关系

本文承接 [程序合成计划](synthesis-plan.md)，描述其范围之外的多源学习与代码/权重联合演化，不替换现有 L1–L4 实现状态。

以下是需要评审的扩展，不静默修改 [ADR-016](adrs.md) 的已采纳合同：

- 数值任务中的 eval 裁判，扩展为“执行器提供行为事实，独立任务合同判断质量”。多模态输出正确性不能由 eval 本身提供。
- 随机性不再只位于提议边界；训练和部分宿主计算也可能随机。记录可回放与训练逐位复现必须分开声明。
- 现有候选文本协议继续描述当前算术学习器；通用模型需要带基础版本和参数制品的候选合同，不能假装只是加几个 config 字段。
- 张量训练由外部宿主执行。Zio 持有程序表示、学习策略和组合逻辑，不在 core 内实现自动微分引擎。

## 2. 库、宿主、产品的边界

| 层 | 拥有的职责 | 不拥有的职责 |
|---|---|---|
| Zio 学习库 | 模型描述、反馈归一化、样本构建、候选搜索、训练编排、评价决策、经验复用 | UI、账号系统、GPU 内核、任意部署权限 |
| 宿主能力 | 多模态编解码、模型推理、张量训练、制品读写、隔离执行、硬资源限制 | 自行决定学习目标或批准模型晋升 |
| 产品壳 | 教师连接配置、纠错界面、运行查看、人工审批、部署装配 | 再实现一份学习算法或绕过库的验证流程 |

这些是逻辑边界，不要求拆成微服务。第一套产品可单机运行，训练任务可由宿主管理的独立工作进程执行；不依赖当前 AST 解释器尚未提供的真实并发语义。

库返回晋升决定和不可变候选；受授权的发布控制器执行原子切换。产品可以批准更严格的发布政策，不能绕过硬安全门槛。

### 2.1 实现基线与部署边界

以下是本设计选择，不是当前仓库能力：

| 位置 | 职责与实现选择 |
|---|---|
| `lib/zio/learn.zio`、`proposer.zio` 及学习子模块 | 统一任务策略、候选生成、反馈使用政策、群体选择、能力抽象；现有数值学习作为同一系统中的任务适配 |
| `ai/`（已有 `zio-ai`） | 保留模型供应商边界；增加有能力声明的教师/多模态接口，不承担历史库或产品业务 |
| `learning/`（`grove`，已实现） | 对 Zio 外部 attach 的可信宿主：合同编解码、SQLite、制品、进程管理、预算、检查点提交和发布事务 |
| `workers/torch/`（已实现） | Python/PyTorch 参考训练后端；CPU 可验证小型任务，GPU 是加速选项；仅执行许可算子图，不 eval 任意 Python |
| `app/`（`grove-app`，二进制 `grove`，已实现） | 本地 CLI 与 HTTP API，Rust/Axum 装配；依赖学习库/宿主，不复制算法 |
| `app/web/`（拟新增） | 普通 HTML/CSS/JS 产品界面；与 API 同源，不复用展示用 landing page 冒充管理产品 |

上述新增依赖均待实施阶段按兼容版本固定；当前默认 CLI 不要求安装 Python 或 PyTorch。训练后端未安装返回明确 capability 错误，不降级为模拟训练。

workspace 依赖保持单向：core 不依赖 AI/学习/产品；AI 与学习宿主使用 core 的公开扩展点；产品装配 AI、学习宿主和 Zio 库。不在 core 新增领域特殊形式。现有 CLI 保留普通脚本用途；产品使用独立二进制，不把 REPL 主程序膨胀成服务管理器。

### 2.2 数据与执行边界

单机采用一个可信协调者、SQLite 事务和本地内容寻址制品目录。不在进程间共享 `Value` 或 `EvalContext`；跨进程只传受版本约束的数据和制品引用。

- SQLite 持有观察/预测/信号元数据、数据视图、谱系、分支 head、运行状态、预算账本、评价和发布指针；所有写入经宿主校验和授权。
- 大型原始输入、权重、参数状态以不可变制品存放。内容摘要校验实际字节；清单记录 schema、依赖和文件摘要，不仅记录可变路径。冻结清单使用确定性编码，禁止 NaN/Infinity 等不稳定数值表示。
- 持久化顺序为临时写入、同步/校验、提交制品、事务提交清单与引用。数据库失败留下未引用制品可后续清理；不能出现已提交清单引用尚未落盘制品。
- 训练 worker 使用版本化、限长的 NDJSON 控制消息；消息包含 request/run/attempt ID。张量不塞进消息，stdout 仅协议、stderr 为限量日志；退出/超时产生显式终态。
- 宿主验证消息大小、schema、引用权限和路径；仅许可可执行文件与参数，禁止候选提供 shell 命令或任意 Python 源码。下载的模型制品视为不可信，不允许反序列化时执行代码。
- 不可信 Zio 候选在独立、受约束的求值进程中运行；训练进程也受进程树、墙钟、内存/设备配额及网络策略限制。仅有白名单或 catch 不能代替可终止的隔离边界。

纯策略库提出选择，宿主检查资源和权限并执行事务。策略代码不能通过直接写数据库、改账本或调用任意进程绕过控制层。

### 2.3 产品 API 与权限

产品 API 映射第 4.2 节操作，不形成第二套模型；耗时操作返回 run ID，查询状态与事件不阻塞浏览器。修改操作使用幂等操作 ID，head/发布切换携带 expected-version；冲突返回显式错误。

事件至少包括信号接收/拒绝、数据视图冻结、候选生成/拒绝、训练进度、检查点提交、评价完成、分支变更、发布与撤回。事件带关联 ID，敏感内容和密钥不写普通日志。

默认绑定 loopback、单用户本地模式；写操作仍校验令牌/来源，不把 localhost 当成免鉴权。角色能力区分 reader、annotator、operator、publisher；人类标注与启动训练、发布模型不是同一种权限。网络部署需显式启用认证、TLS 入口及数据隔离，未配置时拒绝非本地暴露。

统一错误类别：invalid-input、capability-denied、conflict、incompatible-state、budget-exhausted、artifact-unavailable、timeout、cancelled、backend-failed；记录可供机器判断的类别和必要上下文，不依赖匹配错误文本。

## 3. 原语：模型、观察、反馈、经验

### 3.1 模型快照 ModelSnapshot

一个版本绑定程序入口、依赖闭包、参数清单、预处理版本、运行状态结构和运行时兼容要求。参数清单记录形状、dtype、约束、所属模块及制品内容摘要。

发布模型与训练检查点分开：ModelSnapshot 用于执行和评价；Checkpoint 引用该快照，额外保存恢复学习所需状态。只保存权重属于初始化来源，不得声称完整续训。检查点合同见第 6.1 节。

程序与权重共同组成不可变快照；旧版本不通过可变引用读取新权重。持久状态模型要有状态迁移或重置政策，不能把代码切换等同于整个系统回滚。

### 3.2 观察 Observation

包含观察 ID、任务/会话 ID、带类型的内容块、来源、事件时间、必要的空间信息、质量/缺失标记与数据使用权限。内容块支持文本、图像、音频、视频区间、结构化数值；大数据使用受控制品引用。

派生特征保留原始证据引用、编码器版本、单位和对齐信息。内容相似不代表同一观察；不同时间或来源的样本不能仅凭内容哈希合并。

### 3.3 预测 Prediction

记录预测 ID、观察 ID、模型快照、输出和必要的执行证据。人类反馈、教师对照和延迟环境结果必须引用具体预测，而不是仅引用“当前模型”。

### 3.4 学习信号 LearningSignal

统一信封包含：

- 信号 ID、生产者及生产者范围内幂等键；
- 目标任务、观察/预测/候选 ID 与目标输出字段；
- 信号类型、带类型的内容、来源、发生时间和接收时间；
- 标注者或教师版本、生成配置、证据；
- 使用许可、允许的用途、有效范围；
- 修订/撤回所针对的信号 ID。

信封不等于真值。生产者自报置信度只是元数据；有效权重和使用政策由受保护、版本化的样本构建规则决定。

### 3.5 经验 Experience

连接任务、模型版本、训练数据版本、候选变更、反馈、评价和成本。保存失败与拒绝原因，避免只留下成功案例产生选择偏差；保留规模受预算和数据许可限制。

### 3.6 历史与群体对象

| 对象 | 身份与用途 |
|---|---|
| Checkpoint | 不可变学习状态，引用 ModelSnapshot；可恢复级别显式 |
| Branch | 独立研究方向，具有可比较后更新的 head 指针和分支策略；不是可变模型本体 |
| Population | 一组候选分支、总预算、调度/选择策略及版本化成员记录；不是全体分支同时执行的承诺 |
| EvaluationRecord | 绑定模型快照、评价协议、数据、资源条件、重复试验和指标；分数不作为模型固有属性 |

谱系节点是不可变检查点，以有向无环图记录父节点；分裂产生子节点，多来源组合可以有多个父节点。边记录参数训练、代码改写、权重迁移、模块组合或蒸馏的具体来源，不能仅用一个“merge”标签省略过程。运行中的工作状态可变，但不供其他分支作为稳定依赖。

### 3.7 任务、数据与方法合同

TaskContract 绑定任务版本、输入/输出 schema、可调用模块与效果权限、可修改区域、评价指标/硬门槛、独立验收政策以及资源上限。改变评分或安全门槛产生新合同，不能在同一次候选评比中偷偷替换。

DatasetRevision 是冻结的观察/信号引用集合，记录来源许可、转换规则版本、分割清单及撤回状态。训练、验证、独立验收按实体/会话及派生关系隔离，而非单纯随机逐行切分。

Recipe 声明消费哪些信号、训练哪些参数/程序区域、损失/搜索方法、初始化及恢复兼容条件。Run 固定 TaskContract、DatasetRevision、Recipe 和基础快照，后来的反馈只进入下一数据版本。

Candidate 表达基础版本、程序变化、参数制品、依赖及来源；尚未完成训练的候选标记为不可发布。EvaluationRecord 外置于候选，允许同一快照在不同协议下被评价而不改变其身份。

各合同有 schema-version；未知版本拒绝执行，迁移生成新记录并保留来源。不能依靠随意增添字段和忽略未知值实现“兼容”。

## 4. 多种学习接口：来源与算法分离

来源负责产生信号，学习方法负责消费适合自己的信号。不得为每个来源建立一套独立学习循环，也不得把所有信号变成一个通用标量奖励。

### 4.1 学习来源

| 来源 | 信号内容 | 可用学习方式 | 关键边界 |
|---|---|---|---|
| 上游教师硬输出 | 输入与教师结果、教师版本 | 监督蒸馏、行为模仿、程序拟合 | 属于伪标签，不自动覆盖真实标签 |
| 上游教师软输出 | 概率或 logits 及其语义 | 分布蒸馏 | 必须有授权、能力支持与类别/词表对齐 |
| 人类纠正 | 原预测、正确值、修改字段与适用范围 | 监督训练、定向程序修复 | 默认只纠正该目标，不自动泛化成全局规则 |
| 人类偏好 | 同一任务的两个输出及选择/平局/弃权 | 排序、适用模型的偏好优化 | 偏好不是标准答案；需记录展示版本 |
| 人类演示 | 观察、动作、后续状态 | 模仿学习 | 单次成功轨迹不证明每一步都因果有效 |
| 环境结果 | 延迟结果、奖励、成功/失败事件 | 监督学习、强化学习、代码评价 | 必须关联原预测/动作，声明归因方式 |
| 自监督 | 配对模态、遮蔽目标、时序关系 | 表示学习、预测训练 | 代理损失下降不等于任务质量提高 |
| 验证器 | 违反性质、执行失败、反例 | 候选淘汰、程序修复 | 验证范围和版本显式，有限测试不是形式证明 |

### 4.2 最小对外操作（合同记法）

| 操作 | 输入 → 输出 | 语义 |
|---|---|---|
| `observe` | Observation → receipt | 校验并保存观察；不自动学习 |
| `predict` | ModelSnapshot + observation ID → Prediction | 在指定版本执行，建立反馈关联 |
| `submit-signal` | LearningSignal → accepted / duplicate / rejected | 入库回执，不等于样本有效或模型已更新 |
| `request-teacher` | 授权观察引用 + 教师能力 + 预算 → 查询任务回执 | 可异步完成，最终产生教师信号；失败保持可见 |
| `start-learning` | TaskContract + 基础快照 + DatasetRevision + Recipe + budget → run ID | 消费冻结数据视图，不边训练边改变样本含义 |
| `inspect-run` | run ID → 状态、候选与评价引用 | 区分训练失败、评价不通过和发布成功 |
| `promote` | 通过验收的候选 + 授权 + 预期基础版本 → 发布结果 | 基础版本已变化时拒绝陈旧切换 |
| `checkpoint` | run ID + 一致性边界 → Checkpoint | 在完整训练步/代际边界保存；制品完整后才提交可见清单 |
| `fork` | Checkpoint + 分支配置 + 预算配额 → Branch | 创建新方向；改变结构或训练配置时声明状态继承/重置规则 |
| `resume` | Checkpoint + 宿主能力 → run ID / 不兼容错误 | 按声明恢复级别启动；不兼容时拒绝，不偷偷降级为仅加载权重 |
| `pause` | run ID → 暂停请求回执 | 在安全边界提交检查点后才标记 paused；保存失败不可声称已安全暂停 |
| `cancel` | run ID → 取消请求回执 | 停止新工作并请求宿主终止当前工作；已消费预算和已提交历史保留 |
| `compare` | 快照集合 + EvaluationProtocol → EvaluationRecord 集合 | 历史模型在统一条件下重新评价；旧分数不直接混排 |
| `select` | 可比较的评价集合 + 选择策略 → 候选集合及理由 | 可选单个冠军、保留多个专长或形成组合候选；不等于发布 |
| `evolve-population` | Population + 基础检查点集合 → 群体运行 ID | 分配预算、调度、分裂、迁移和暂停；复用单分支学习与评价合同 |
| `compose` | 基础快照 + 模块替换/路由描述 → 新候选快照 | 校验版本、语义、参数耦合和权限；组合后必须整体评价 |

修订与撤回通过 `submit-signal` 的显式信号类型进入。撤回从后续数据视图排除，并标记受影响制品；不声称已有权重已经遗忘该样本。涉及删除权时按策略删除原始数据、最小化审计元数据，并决定重训或退役。

反馈格式与训练方法以显式注册表连接：来源适配器以来源类型分派；样本转换以信号类型和 schema 版本分派；训练执行以学习方法和宿主能力分派。核心循环只消费归一化合同，不分支判断具体教师厂商或 UI。

### 4.3 上游模型蒸馏合同

教师适配器声明可用输入模态、输出 schema、是否支持概率/logits、速率/费用限制、数据保留与训练使用许可。不支持 logits 时使用硬输出蒸馏，不能伪造软标签。

查询只携带经授权的必要内容，不向教师发送独立验收集。记录教师模型标识、提示/配置版本、原始响应及解析状态；供应商不提供精确模型修订时，标记来源版本不完整。

教师可以提出程序，也可以提供目标输出，这是不同角色。教师输出的代码走候选安全检查；教师生成的测试只能作为搜索辅助，不能独自批准它生成的候选。

学习价值按固定外部任务评价：学生未必超过教师，也不要求超过教师；在质量容差内更低成本、更低延迟或满足本地执行要求，同样是有效目标。

### 4.4 人类纠正合同

纠错界面必须显示原观察、原预测和具体模型版本。纠正可以针对字段、区域或时间区间；未修改部分不自动视为人工确认。

默认优先级为：具备该任务标注权限的人类明确纠正可替代同一目标的教师伪标签；互相冲突的人类纠正进入待裁决，不按最后写入者获胜。权限、适用范围和数据使用许可都满足后，才能进入训练视图。

立即生效的人工覆盖与模型学习分开：产品可提供经授权的局部覆盖，但记录为覆盖规则；只有新模型独立验收通过后，才宣称模型已学会。隔离原观察及其派生变体，避免纠正内容同时泄漏进训练和验收。

## 5. 组合与代码组织

### 5.1 能力模块

每个模块声明输入/输出、张量形状与 dtype、语义空间、参数、依赖、可变 AST 区域、梯度边界、效果权限与行为合同。

模型通常是模块组合图；模块内部可以有经约束的分支、循环和显式状态，不要求把所有程序强制表示为无环网络。纯计算与产生外部动作的模块分开，学习候选默认没有真实外部副作用权限。

代码变更限于合同允许的模块替换、连接调整、局部 AST 改写和公共抽象提取。提议器提交候选，不能自由修改仓库、安全策略或验收脚本。

### 5.2 源码与制品的权威性

Zio AST 和模型清单是模型结构的权威表示；后端计算图是从该表示生成的制品，不能另外手写一份结构。权重、数据与生成程序按不可变版本引用；逻辑模块不要求一模块一文件或一服务。

现有 `learn.zio` 与 `proposer.zio` 是复用起点。反馈归一化、模型描述、经验与发布合同属于库职责；是否拆分新文件由实现规模决定。产品代码不进入通用学习库。

### 5.3 可微边界

在可微子图内保留后端梯度关系，Zio 负责组织与控制。不把张量转为普通列表后继续声称梯度可追踪；不对任意 eval、检索、硬分支和工具调用承诺自动求导。

神经网络参数走梯度或明确的优化算法，离散 AST 走结构搜索。软路由、策略梯度等方法需要专门 recipe，不是隐式兜底。

### 5.4 模块检查点与协同演化

整模型检查点是默认单位；独立模块可以另存快照与训练状态，但必须带所属模型、冻结上下文、输入分布/语义空间和依赖版本。与其他模块共享参数、联合优化器状态或不可分离运行状态时，将它们视作同一个演化单元，不伪造独立可恢复模块。

一个分支只演化视觉适配器，另一个只演化融合策略时，其余模块精确绑定到基线版本。模块替换要检查：输入输出合同、编码空间、参数共享、梯度连通、权限闭包和状态迁移。形状相同不代表语义兼容。

模块单测或局部损失用于筛选，不能证明组合后更好。候选模块先在固定上下文评价，再把有价值的组合装入整模型比较；必要时联合微调。记录“模块版本 + 上下文版本 → 贡献”，避免把上下文收益错误归因于模块。

不枚举所有模块版本的笛卡尔积。默认冻结多数模块、局部替换；在总预算内探索少量组合。可逐步增加协同演化策略，但不能降低整模型的回归与独立验收要求。

跨模型复制模块得到新依赖绑定，不允许共享可变权重。若采用共享编码器与多个专家，编码器更新属于所有受影响专家的联合候选，必须重新评价整个依赖闭包。

## 6. 自学习闭环

1. 接收多模态观察，在指定快照上执行并记录预测。
2. 收集教师、人类、环境等信号，验证关联、权限、格式、冲突和用途。
3. 用版本化规则生成冻结数据视图；按会话/实体/来源关系分割，防止近重复泄漏。
4. 检索已有经验；在预算内提出参数适配或程序候选。
5. 检查 AST、模块合同、依赖、梯度边界、权限与资源需求。
6. 固定候选结构，训练允许的参数；必要时在外循环比较多种结构。
7. 比较验证效果、旧任务回归、资源与复杂度，选出候选。
8. 用独立验收合同判断是否可晋升；发布时检查基础版本并整体切换。
9. 记录失败和成功经验；跨任务验证通过的抽象进入能力库。

内循环优化参数，外循环优化代码。结构未变的模块复用权重；变化模块仅在声明兼容且验证通过时迁移权重；新模块初始化训练。不兼容的优化器状态不得复用。

训练、调参用验证集、独立验收集分开；验收集不持续回喂提议器。多次验收也会产生选择偏差，需限制访问并更新独立评估方案。训练记录环境与种子，但 GPU 数值执行不承诺逐位确定性。

学习运行主路径为 queued → running → evaluating → accepted / rejected；任一非终态可在处理失败或取消后进入 failed / cancelled。running / evaluating 可请求 pausing，保存完整状态成功后进入 paused；无法保存评价中间状态时记录从评价阶段起点重跑。resume 创建关联原运行的新 run，从检查点恢复并继承预算账本，原 paused 记录不被覆盖。accepted 仅表示具备发布资格；发布状态单独记录 staged / active / retired。中断不覆盖当前版本。

一个新增反馈只是学习证据，不必立即触发训练。默认批次训练、显式启动；产品可按已批准的触发规则自动启动，不能因用户提交一次纠错便隐式发起高成本训练。

### 6.1 Checkpoint：保存什么、何时可恢复

检查点包含：

- 模型快照与完整制品清单、内容摘要、格式/宿主兼容信息；
- 训练步、优化器、学习率调度器、混合精度缩放器、随机数状态，以及方法实际使用的其他训练状态；
- 数据视图版本、采样器/游标/分片状态；流式环境的来源位置及外部状态是否可恢复；
- 程序搜索的代际、候选池、提议历史、去重状态、提议器版本与已消费响应；
- 学习配置、已消费资源、父检查点、来源信号与操作记录。

同时训练多个 worker 时，由宿主在协调的一致性边界保存，不将不同训练步的张量拼成一个检查点。先写并校验制品，最后原子提交清单；中断产生的半成品不出现在可恢复历史中。

恢复级别必须显式：

| 级别 | 保证 | 不保证 |
|---|---|---|
| 模型初始化 | 加载代码和权重，开启新运行 | 优化器、数据进度或搜索历史连续 |
| 学习续接 | 恢复方法声明的状态、数据位置和预算账本 | 外部教师未来输出、GPU 逐位确定性 |
| 受控轨迹回放 | 在受支持的确定性环境与已记录宿主响应下回放 | 任意外部环境、物理动作或硬件都可重现 |

缺少数据或制品、依赖被撤回、后端不兼容时返回明确失败。用户可以显式选择以权重初始化新运行，但必须记录这是 fork/restart，而非完整 resume。恢复不会自动恢复线上会话状态或撤销外部动作。

分支只共享不可变制品，新增权重写入新制品；可复用相同基础权重并存储适配器差异，不要求立即开发通用张量差分格式。内容摘要用于身份与完整性，不替代授权和安全审查。

### 6.2 历史比较与选择

EvaluationProtocol 固定任务合同、评价数据、预处理、指标、缺失/错误处理、随机种子计划，以及硬件/资源测量口径。历史快照在该协议下重新运行；不能拿旧数据上的 95% 与新数据上的 93% 直接比较。

同时展示整体指标、关键场景切片、回归、时延/内存/费用和统计波动。随机结果按预先约定的重复试验比较；超时或失败不能从分母里静默删除。人工比较隐藏模型身份并控制展示顺序，偏好记录引用准确快照。

区分两类问题：比较部署候选时比较执行质量与成本；比较学习策略时还要统一或报告搜索/训练总预算、教师调用、初始化来源和失败试验成本。不得只计最后一段训练或忽略祖先分支的研究成本。

默认先通过硬门槛，再保留质量/成本上互不支配的候选及有价值的场景专长，最后按部署目标选模型。可发布单个模型，也可产生经整体验证的路由/集成模型；不强制所有任务由唯一冠军覆盖。

搜索使用验证数据，发布使用独立验收。人口越大、比较次数越多，过拟合评价集的风险越高；所有分支共用验收访问预算，不能通过 fork 获得无限次独立验收机会。

### 6.3 分裂、多路并行与群体调度

从同一检查点可分裂出不同方向：参数学习、结构搜索、教师来源、数据子集或模块专长。分支 head 更新使用预期旧版本检查；每次跨分支继承都生成新节点，不覆写被继承历史。

群体的基本循环是：分配预算 → 并行/排队执行 → 保存检查点 → 在可比较进度上评价 → 保留多样性 → 迁移/分裂/暂停 → 继续学习。

并行由宿主工作进程或训练后端调度，不依赖当前 Zio 的同步并发占位原语。单卡可以串行交错执行多分支，多设备可真正并行；逻辑分支数与实际执行槽位分开配置。

Population 持有统一资源账本：训练资源、教师调用、评价、存储、最大活跃槽位及每分支配额。fork 不复制剩余额度，resume 不清零已消耗资源。新分支从父群体获得配额；预算不足则排队、暂停或拒绝，不隐式无限扩张。

默认由一个协调者管理调度与 head，worker 只提交带 run/attempt ID 的结果；租约失效的 worker 不能覆盖新进度。失败可从已提交检查点继续，重试和重复回执按操作 ID 去重。外部付费调用若供应商不支持幂等，则记录“结果未知”并由策略决定是否重试，不承诺跨供应商恰好一次。

为避免快分支因反馈频繁占尽预算，选择策略比较预定资源档位并保留最低探索配额。保留基线、优势候选和行为不同的专长分支；不能只按一个平均分反复复制冠军导致群体同质化。

### 6.4 群体协作不是任意合并

| 协作方式 | 发生阶段 | 合同 |
|---|---|---|
| 经验/反例交换 | 学习 | 通过 LearningSignal 与授权数据视图共享；不传播独立验收答案 |
| 检查点继承 | 学习 | 复制兼容状态形成新后代，调整超参数；按兼容性重置优化器等状态 |
| 模块组合 | 学习/候选构建 | 组合精确版本模块，校验依赖与语义，再整体训练/评价 |
| 多教师蒸馏 | 学习 | 多分支提供有来源的教师结果，蒸馏出单独学生；分歧不强行压成真值 |
| 专家路由 | 推理 | 路由器及专家集合也是版本化模型；验证选错专家、缺失输入和成本 |
| 输出集成 | 推理 | 输出空间兼容，投票/加权/仲裁规则显式；评价相关错误、尾延迟和总资源 |

训练期的分支群体可以最终只发布一个模型；推理期的多模型协作也可以作为一个发布快照。两者分别配置，不因“群体智能”强制每次请求调用所有模型。

代码合并只产生待验证候选，不能等同于语义正确；任意独立模型权重默认禁止直接平均。确需权重融合时，专门方法必须验证架构、参数对齐、初始化谱系及融合后表现。多父谱系记录贡献来源，不表示发生了权重平均。

专家分歧可在查询预算与权限内触发人类或上游教师反馈，形成新的学习信号；一致意见也不保证正确，仍需覆盖群体共同错误的独立评价。路由器/仲裁器的训练与发布遵循同样的边界。

### 6.5 保留、淘汰与产品表面

暂停或淘汰分支只改变调度资格，不自动删除模型历史。活跃部署、分支 head、基线、标记保留项和评价可复现所需检查点固定保留；引用到的依赖制品不能被垃圾回收。设置保留预算，清理未引用且超出政策期限的制品。

清理权重后可以留下最小谱系与指标元数据，但必须将对应节点标为“不可恢复”，不能继续承诺可重跑比较。数据删除义务优先于历史可重现性，相关模型/检查点按撤回政策失效、重训或退役。

产品提供谱系视图、同协议比较表、从历史节点分裂、暂停/续接分支、模块替换差异和发布选择。视图明确区分：可执行、可续训、可回放、已失效，以及“研究优胜”与“已经发布”。人工选择仍不能绕过硬门槛。

## 7. 向量化、经验与抽象

- 感知向量用于任务计算；不同模态需有明确对齐或投影方法。
- 语义向量用于检索历史任务和模块，不作为正确性或权限证据。
- 行为指纹比较同一输入合同及探针集上的输出；不同探针版本不可直接混比。
- AST 结构索引用于结构复用和候选去重；embedding 相似不能证明程序等价。

向量绑定编码器版本和空间标识，编码器变化时重建索引或显式迁移。规模未要求专用向量数据库前，不以部署数据库作为架构前提。

经验抽象优先提取普通函数；必要时才生成宏。宏展开后的依赖与权限仍需校验。程序压缩指标计入新能力库定义成本，不能把长程序藏进函数名就宣称学习成功。

学习器本身的演化是候选扩展，不在本稿视为已批准：提议模型/训练策略可以在独立任务集合上评价后更新，但外层权限、评价与发布控制不由候选修改。

## 8. 抽象屏障与扩展验收

| 屏障 | 上层知道什么 | 下层可以替换什么 | 扩展验收 |
|---|---|---|---|
| B0 观察 | 内容类型、证据引用与对齐合同 | 编解码/存储实现 | 已支持模态新增供应商不改学习循环；新增模态只增加 schema、适配器及相关能力模块 |
| B1 信号 | 归一化信号及用途 | 教师或人类交互渠道 | 新教师或纠错界面不改训练算法 |
| B2 模型模块 | 类型、效果、参数与梯度合同 | 符合合同的模块实现 | 替换编码器需兼容验证，不改反馈接口 |
| B3 学习方法 | 数据视图、候选、预算与评价 | 梯度训练、程序搜索等 recipe | 新方法不改教师/人类信号生产者 |
| B4 发布 | 不可变快照、证据与资格 | 产品审批界面或部署方式 | 更换 UI 不得绕过相同晋升约束 |
| B5 历史与群体 | 不可变检查点、兼容级别、统一预算和评价协议 | 调度策略、存储布局、串行/并行 worker | 增加分支或执行槽位不改学习来源接口，不绕过总预算与发布门槛 |

边界检查与资源限制由可信宿主执行；候选可写代码不能关闭它们。候选代码只允许受控能力，检查宏展开与依赖传递后的权限；AST 大小限制不能替代运行时间、内存、训练步数与外部调用预算。

## 9. 贯穿示例：教师初学、人类纠正、程序与权重协同更新

任务：依据设备图片和传感器读数判断设备状态。

1. 上游多模态教师为授权观察提供状态伪标签，记录教师来源；少量人工确认与真实结果构成独立评估依据。
2. 学生模型先学习视觉适配器、数值处理和融合模块，实现本地预测。
3. 人类纠正一次“异常”预测为“正常”，标注具体观察及反光区域；未确认的其他输出字段不追加人工标签。
4. 样本规则以该纠正替换同目标的教师伪标签，保留修订关系。训练视图与独立验收视图隔离。
5. 从同一检查点分裂两个分支：参数分支调整视觉适配器；结构分支尝试依赖传感器历史的融合程序，并训练新增模块。两路在总预算内并行或交错执行；若无合法历史数据，结构分支不可凭空构造。
6. 将旧快照及两路候选在同一协议下比较，覆盖反光场景、旧场景、缺失传感器场景及成本。若尝试组合视觉模块和新融合程序，组合体作为新候选重新评价，不把两个局部得分直接相加。
7. 满足独立验收合同的模型才整体切换；其余有价值的分支可保留或暂停。下一次类似任务可以检索或分裂历史方案，但仍需重新验证，不能把一次纠正当作全局定律。

这些是预期行为，不是已执行的实验结果。

## 10. 分阶段交付与可观察验收

| 阶段 | 交付 | 验收 |
|---|---|---|
| P1 多源证据与模型身份 | 快照、反馈关联、教师硬输出、人类纠正、冻结数据视图、检查点清单与历史引用 | 重复反馈不重复计入；迟到纠正命中原版本；半成品检查点不可见；不可恢复状态明确；未授权来源不能更新模型 |
| P2 真实双学习闭环与分支 | 可训练子图、受限程序搜索、检查点恢复、分裂及同协议比较选择 | 实际训练权重与生成结构候选；中断后按声明级别恢复；子分支不改祖先；历史模型统一重评；比较固定模型/仅调参两组；失败不覆盖旧版 |
| P3 多模态群体产品闭环 | 教师查询、纠错界面、谱系比较、预算内多路学习、发布/回滚 | 实际多 worker 并行运行；总预算不因分裂翻倍；陈旧 worker 不能覆盖 head；可暂停续接和选择历史模型；撤回标记受影响制品 |
| P4 模块协同与经验抽象 | 模块分支、组合验证、经验检索、公共函数提取、专家路由/输出集成 | 共享参数模块作为联合单元；两个局部优势不替代整体验证；无效组合被拒绝；组合模型按总推理成本验收；新任务验证复用收益及完整描述长度 |

P1–P4 是本提案自己的交付编号，不是对原 L1–L4 的重命名。P2 的双学习是必要交付，不能用仅调用上游模型或仅调提示词代替。每个真实任务的质量容差、预算与回归门槛必须在实验前写入 TaskContract，不在架构层虚构统一数值。

## 11. 风险、非目标与待确认边界

- 上游教师的可调用性不等于其输出可用于训练；宿主需核实许可和数据外传范围。
- 人类反馈会有冲突、错误和恶意输入；身份与任务权限不能省略。
- 自动学习不保证单调改进；保存旧版本并允许拒绝所有候选是正常结果。
- 已发布模型的回滚不撤销外部动作，也不自动恢复不兼容运行状态。
- 检查点续接不保证外部环境可回放；存储清理和数据撤回会使部分历史不可恢复。
- 群体规模会放大训练费用与评价过拟合；公平比较、多样性保留与全局预算是必要约束，而不是无限复制分支。
- 不以自研张量引擎、通用分布式训练、自动修改 Zio core 为本架构前提。
- 本稿不承诺开放任务的完全自主学习，也不将人类审阅阶段标为实现完成。

落地前置条件不阻塞设计交付：真实应用需提供有使用许可的数据、独立效果反馈、教师访问条件和资源预算。计划提供可自行生成的技术验收任务，覆盖真实训练与结构演化，但不把该任务的成功解释为真实业务有效。学习器自身改写不纳入 P1–P4 自动发布范围；其提议器、recipe 和调度策略已版本化，可由受授权发布者替换。真正的元学习自动晋升需独立任务集合评价与后续明确授权。
